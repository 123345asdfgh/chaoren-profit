## 商品基础信息

“统一配置”旁的“商品录入”打开商品资料弹窗，上方录入、下方以表格查看。支持商品名称、规格编码、商品编码和属性组合查询：名称与编码按文本包含匹配、忽略英文大小写，属性精确匹配，各条件取交集；未填写的条件不限制结果，重置显示全部。编码保留前导 0，百分号和下划线按普通字符搜索。支持每页 10/20/50 条、修改和删除已有资料；删除前显示自定义确认弹窗，删除商品资料不影响已保存的历史测算。商品名称去除首尾空白、合并连续空白并忽略英文字母大小写后判重，数据库唯一约束防止并发重复录入。

商品库保存名称、规格编码、商品编码、商品属性、长宽高和实重；两个编码以文本存储并保留前导 0；尺寸类型（包裹/裸货）和店铺在每次测算时现场选择。计算页输入已录入商品的完整名称会自动回填，输入部分名称可选择匹配商品；编码、属性、长宽高和实重均只展示，需修改基础资料时在商品录入弹窗操作。旧商品缺少编码时显示为空，可点击“修改”补齐后使用。更换或清空商品名时清空旧商品的编码、属性和尺寸展示，避免沿用其他商品的数据。历史记录载入仍使用当时保存的快照，商品库更新不改写旧记录。保存测算与商品录入分别操作。

商品编码全库唯一，忽略首尾空格与英文字母大小写，前导 0 保留。数据库唯一索引同时约束新增、修改和并发写入；修改原商品时可保留自己的编码，不能使用其他商品的编码。重复时提示“商品编码已存在，请使用其他编码，或修改已有商品资料。”规格编码不作唯一限制，历史测算中的编码快照也不受商品库唯一限制。旧商品尚未补齐的空编码保留兼容，新录入及修改仍要求填写编码。旧库有重复商品编码时，迁移会报错，应先确认正确编码后修正，不自动删除或重编号。

更换或清空商品名时，同时清空上一件商品的物流成本和利润结果；重新匹配有效商品后再自动估算。物流参数变化后，如果实重或材积对应的计费重超出当前渠道上限、没有匹配运价档位或输入无效，清空旧估算，使用红字说明原因，可人工填写实际物流成本继续测算。未录入商品、缺少编码和表单输入错误也用红字提示；恢复有效输入后解除错误样式。载入历史与初次打开对比时，保留快照中已确认的手动成本。

## 本地启动

要求 Node.js 24+、pnpm 11+ 和 PostgreSQL。数据库名称必须是 `chaoren_profit_dev`；后端会拒绝连接其他库。按 `.env.example` 配置 `.env.local` 中的本机数据库连接。

```sh
pnpm install
pnpm db:migrate
pnpm dev
```

Web 默认地址为 http://127.0.0.1:8081，API 默认监听 127.0.0.1:3002。

验证命令：`pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm --filter @profit/api smoke`。冒烟测试会创建临时测算记录，并在结束后清理。商品库验证命令：`pnpm --filter @profit/api products:smoke`，覆盖持久化、名称判重、并发写入、查询、分页、修改及删除，结束后只清理其临时商品。

## 数据与版本

独立 `profit` schema 中的 `records` 保存所有人的记录，`products` 保存共享商品基础信息，`calculation_defaults` 按身份保存每个用户自己的配置。系统初始配置表已移除；初始参数与内部物流规则来自代码。旧版 `users`、`sessions` 和 `user_settings` 表保留，以兼容现有数据，但当前业务流程不使用它们。新记录不保存订单编号和商品规格；旧记录的这两列原值保留。新单保存时总是新增记录，即使商品编码相同；载入历史记录后再保存，才按记录 ID 修改，并把原快照转为 `previous_snapshot`、新方案作为当前版。恢复上一版时两份快照和版本号一起交换，例如第 3 版恢复后显示第 2 版，且可切回第 3 版。目前只保留一份上一版。

利润输入和计算结果保存在 JSONB 快照中，利润另存数值列供统计。物流长宽高、实重、尺寸类型、店铺及本版本完整物流配置均写入 JSONB 快照，预计运费由后端按快照重新计算并独立保存。历史详情、载入修改、版本回溯和 Excel 导出均使用该版本快照；旧版未保存的物流字段显示为未记录。数据库迁移不再清除物流字段。对比临时设置没有独立配置表，也不修改统一配置；接受新方案时，利润参数和最终采用的物流成本进入历史版本；临时物流渠道配置也进入当前历史版本，载入修改后使用本记录配置，不影响统一配置。当前只支持美国市场，数据模型保留 `market` 字段供未来扩展。Excel 导入及主工作台集成尚未实现。
